## File Naming Conventions

### Python Modules
- snake_case for files: `user_service.py`
- PascalCase for classes: `UserService`
- snake_case for functions: `create_user()`

### Test Files
- Prefix with `test_`: `test_user_service.py`
- Mirror source structure

### Configuration Files
- Lowercase with hyphens: `docker-compose.yml`
- Hidden for system files: `.env`

## Import Organization

```python
# Standard library imports
import os
from typing import List, Optional

# Third-party imports
from fastapi import APIRouter
from sqlalchemy import Column, String

# Local application imports
from src.models.base import BaseModel
from src.services.user_service import UserService
```

## Module Responsibilities

### models/

- **Purpose**: Define data structures and ORM mappings
- **Contains**: Database models, validation rules
- **Does NOT contain**: Business logic, API logic

### repositories/

- **Purpose**: Data access abstraction
- **Contains**: CRUD operations, queries
- **Does NOT contain**: Business rules, API logic

### services/

- **Purpose**: Business logic implementation
- **Contains**: Complex operations, business rules
- **Does NOT contain**: HTTP logic, database queries (uses repositories)

### api/

- **Purpose**: HTTP interface
- **Contains**: Routes, request/response handling
- **Does NOT contain**: Business logic (uses services)

## Configuration Management

### Environment Variables

```bash
# .env.example
DATABASE_URL=postgresql://user:pass@localhost/db
SECRET_KEY=your-secret-key
DEBUG=False
LOG_LEVEL=INFO
```

### Settings Module

```python
# config/settings.py
from pydantic import BaseSettings

class Settings(BaseSettings):
    database_url: str
    secret_key: str
    debug: bool = False
    
    class Config:
        env_file = ".env"
```

## Testing Structure

### Unit Tests

- Test individual functions/methods in isolation
- Mock external dependencies
- Fast execution

### Integration Tests

- Test component interactions
- Use test database
- Slower but more comprehensive
