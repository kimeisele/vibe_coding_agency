# GRAND AGENCY CODE AI FRAMEWORK

## Master Orchestration Document v1.0

### PURPOSE

This framework enables semi-autonomous AI-driven software project management from inception through implementation. Designed for LLM consumption, not human readability.

-----

## FRAMEWORK ARCHITECTURE

### CORE COMPONENTS

1. PROJECT_INTAKE - Initial classification and scoping
1. ARCHITECTURE_DESIGN - Technical specification generation
1. IMPLEMENTATION_PLAN - Executable roadmap creation
1. CODE_GENERATION - Structured development phase
1. QUALITY_ASSURANCE - Validation and testing
1. PROJECT_RECOVERY - Legacy project remediation

-----

## DECISION TREE: PROJECT CLASSIFICATION

```
INPUT: Project context
│
├─→ NEW_PROJECT
│   ├─→ Criteria: No existing codebase
│   ├─→ Flow: INTAKE → DESIGN → PLAN → GENERATE → QA
│   └─→ Templates: NEW_PROJECT_*
│
└─→ EXISTING_PROJECT
    ├─→ Criteria: Has codebase (chaotic or structured)
    ├─→ Flow: AUDIT → TRIAGE → RECOVERY → PLAN → QA
    └─→ Templates: LEGACY_PROJECT_*
```

-----

## PHASE DEFINITIONS

### PHASE 1: PROJECT_INTAKE

**Trigger**: User provides project description
**AI Role**: Structured information extraction
**Required Outputs**:

- `PROJECT_BRIEF.md` - Structured project overview
- `REQUIREMENTS_SPEC.md` - Functional requirements
- `SUCCESS_METRICS.md` - Measurable outcomes
- `CONSTRAINTS.md` - Technical/business limitations

**Validation Criteria**:

- [ ] Clear problem statement exists
- [ ] At least 3 measurable success metrics defined
- [ ] Technical constraints identified
- [ ] Scope boundaries explicitly stated

**Proceed to**: ARCHITECTURE_DESIGN

-----

### PHASE 2: ARCHITECTURE_DESIGN

**Trigger**: PROJECT_INTAKE validation passed
**AI Role**: Technical architecture specification
**Required Outputs**:

- `SYSTEM_ARCHITECTURE.md` - High-level system design
- `DATA_MODEL.md` - Database/data structure specification
- `API_SPEC.md` - Interface definitions (if applicable)
- `TECH_STACK.md` - Technology selection with justification

**Validation Criteria**:

- [ ] Architecture supports all requirements
- [ ] Data model normalized and documented
- [ ] Technology choices justified
- [ ] Scalability considerations addressed

**Proceed to**: IMPLEMENTATION_PLAN

-----

### PHASE 3: IMPLEMENTATION_PLAN

**Trigger**: ARCHITECTURE_DESIGN validation passed
**AI Role**: Decompose architecture into implementable units
**Required Outputs**:

- `USER_STORIES.md` - Feature breakdown
- `TECHNICAL_TASKS.md` - Development task list
- `PROJECT_STRUCTURE.md` - Directory/file organization
- `DEPENDENCIES.md` - External libraries and services

**Validation Criteria**:

- [ ] All features mapped to tasks
- [ ] Task dependencies identified
- [ ] File structure follows best practices
- [ ] No circular dependencies

**Proceed to**: CODE_GENERATION

-----

### PHASE 4: CODE_GENERATION

**Trigger**: IMPLEMENTATION_PLAN validation passed
**AI Role**: Structured code implementation
**Required Outputs**:

- Working codebase following PROJECT_STRUCTURE
- `CODE_STANDARDS.md` - Style guide used
- `IMPLEMENTATION_NOTES.md` - Key decisions documented
- Unit tests for core functionality

**Validation Criteria**:

- [ ] Code follows single responsibility principle
- [ ] Functions documented with docstrings
- [ ] Error handling implemented
- [ ] No hardcoded credentials or secrets

**Proceed to**: QUALITY_ASSURANCE

-----

### PHASE 5: QUALITY_ASSURANCE

**Trigger**: CODE_GENERATION completed
**AI Role**: Validation and testing
**Required Outputs**:

- `TEST_REPORT.md` - Test results
- `CODE_REVIEW.md` - Self-review findings
- `DEPLOYMENT_CHECKLIST.md` - Production readiness
- `MAINTENANCE_GUIDE.md` - Ongoing support documentation

**Validation Criteria**:

- [ ] All critical paths tested
- [ ] No high-severity issues remain
- [ ] Documentation complete
- [ ] Deployment process documented

**Project Status**: COMPLETE

-----

### PHASE 6: PROJECT_RECOVERY (For Existing Projects)

**Trigger**: User provides existing codebase
**AI Role**: Audit and remediation planning
**Required Outputs**:

- `CODEBASE_AUDIT.md` - Current state analysis
- `ISSUES_INVENTORY.md` - Problems categorized by severity
- `RECOVERY_PLAN.md` - Remediation roadmap
- `REFACTOR_PRIORITY.md` - Ordered list of fixes

**Sub-phases**:

1. **AUDIT**: Analyze existing code structure
1. **TRIAGE**: Categorize issues (critical/major/minor)
1. **STABILIZE**: Fix critical issues first
1. **REFACTOR**: Improve architecture incrementally
1. **DOCUMENT**: Create missing specifications

**Validation Criteria**:

- [ ] All files analyzed
- [ ] Critical bugs identified
- [ ] Architecture gaps documented
- [ ] Recovery plan has clear milestones

**Proceed to**: IMPLEMENTATION_PLAN (modified for refactoring)

## EXECUTION PROTOCOL

### FOR AI AGENTS:

1. **IDENTIFY PROJECT TYPE**
- Request: “Classify this project as NEW or EXISTING”
- If ambiguous: Request codebase or clarification
1. **EXECUTE PHASE SEQUENCE**
- Load appropriate phase template
- Generate required outputs
- Self-validate against criteria
- Report completion or blockers
1. **MAINTAIN STATE**
- Track current phase
- Store all artifacts in structured format
- Reference previous phase outputs
1. **HANDLE ERRORS**
- If validation fails: Document reason, request input
- If ambiguous: Ask clarifying questions
- Never proceed with invalid phase outputs

-----

## QUALITY GATES

Each phase has **mandatory validation**. AI must not proceed if:

- Required outputs missing
- Validation criteria not met
- Logical inconsistencies detected
- User approval required but not obtained

-----

## FRAMEWORK INVOCATION

To use this framework, AI should:

1. Load all framework documents into context
1. Request project context from user
1. Execute decision tree to determine flow
1. Begin Phase 1 with appropriate template
1. Iterate through phases until completion

-----

## EXTENSIBILITY

Framework supports:

- Custom phase additions
- Modified validation criteria
- Domain-specific templates
- Alternative workflows for specialized projects
