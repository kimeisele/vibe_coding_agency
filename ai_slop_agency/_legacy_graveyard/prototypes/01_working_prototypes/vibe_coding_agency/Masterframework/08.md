# FRAMEWORK QUICK START GUIDE

## How to Use This Framework

-----

## FOR AI AGENTS

This guide explains how to use the Grand Agency Code AI Framework.

-----

## STEP 1: LOAD FRAMEWORK

Load these files into your context:

**Required (always load)**:

- `MASTER_FRAMEWORK.md` - Core orchestration
- Decision tree for project type
- Phase definitions

**Load as needed based on project type**:

- `TEMPLATE_NEW_PROJECT_INTAKE.md` - For new projects
- `TEMPLATE_EXISTING_PROJECT_RECOVERY.md` - For existing/chaotic codebases
- `TEMPLATE_ARCHITECTURE_DESIGN.md` - For Phase 2
- `TEMPLATE_IMPLEMENTATION_PLAN.md` - For Phase 3
- `TEMPLATE_CODE_GENERATION.md` - For Phase 4
- `TEMPLATE_QUALITY_ASSURANCE.md` - For Phase 5

-----

## STEP 2: CLASSIFY PROJECT

Ask user:

```
"Is this:
A) A NEW project (no existing code)
B) An EXISTING project (has codebase that needs help)

For existing projects, can you provide:
- GitHub repository URL, or
- Uploaded files, or
- Description of current state"
```

### If NEW PROJECT:

→ Go to Phase 1 (Intake) using `TEMPLATE_NEW_PROJECT_INTAKE.md`

### If EXISTING PROJECT:

→ Go to Phase 6 (Recovery) using `TEMPLATE_EXISTING_PROJECT_RECOVERY.md`

-----

### For NEW Projects:

```

↓

Validate outputs
↓
Phase 3: IMPLEMENTATION_PLAN
↓
Load TEMPLATE_IMPLEMENTATION_PLAN.md
Break down into tasks
Generate: USER_STORIES.md, TECHNICAL_TASKS.md, PROJECT_STRUCTURE.md, DEPENDENCIES.md
Validate outputs
↓
Phase 4: CODE_GENERATION
↓
Load TEMPLATE_CODE_GENERATION.md
Implement code following standards
```

### For EXISTING Projects:

```

↓
Load TEMPLATE_EXISTING_PROJECT_RECOVERY.md
Audit codebase

↓

↓

↓

↓

↓

↓
Validate improvements
↓
PROJECT RECOVERED
```

## STEP 4: VALIDATE EACH PHASE

After completing each phase:

1. **Check validation criteria** (at end of each template)
1. **Verify all required outputs generated**
1. **Ensure no logical inconsistencies**
1. **Do NOT proceed if validation fails**

-----

## STEP 5: MAINTAIN STATE

Throughout execution:

- **Track current phase**: Always know where you are
- **Reference previous outputs**: Use artifacts from earlier phases
- **Document decisions**: Record key choices in IMPLEMENTATION_NOTES.md
- **Update user regularly**: Report progress and blockers

## COMMON PATTERNS

### Pattern: User Provides Vague Input

```
USER: "Make me something cool"

AI: "I need more specific information to help effectively. Let me ask:

1. What type of application? (web, mobile, CLI, API, data processing, etc.)
2. What's the core purpose?
3. Who will use it?
4. Any specific features in mind?

Think of it as if you're a customer describing needs to an agency."
```

### Pattern: User Provides Incomplete Information

```
AI: "I've extracted the following from your description:
- Problem: [X]
- Users: [Y]
- Core Features: [Z]

I'm missing:
- Technical constraints (any required tech?)
- Success metrics (how do we know it works?)
- Scope boundaries (what's NOT included?)

Please provide these so I can create complete specifications."
```

### Pattern: Validation Fails

```
AI: "✗ Phase validation FAILED

Issue: Requirements contain contradictions:
- Requirement 1 states: Must work offline
- Requirement 3 states: Real-time syncing required

These conflict because real-time syncing requires connectivity.

Please clarify priority or approach."
```

### Pattern: User Wants to Skip Phase

```
USER: "Just code it, don't do all the planning"

AI: "I understand the desire to move quickly. However, this framework prevents 
the exact problems you've experienced before (chaotic code, unclear structure).

I can move FASTER through planning phases for simple projects, but skipping 
them entirely will likely recreate the 'AI slop' and 'wildwuchs' problems.

Would you like me to:
A) Quick planning (minimal but sufficient docs)
B) Full planning (comprehensive)
C) Explain why skipping causes issues"
```

## BEST PRACTICES FOR AI AGENTS

1. **Always load the appropriate template before starting a phase**
- Don’t rely on memory
- Templates contain critical details
1. **Follow the validation checklists**
- They prevent compounding errors
- Catch issues early
1. **Generate ALL required artifacts**
- User needs these for continuity
- Other AI sessions need these documents
1. **Be explicit about current state**
- Tell user what phase you’re in
- Show what’s been completed
- Indicate what’s next
1. **Ask for clarification when needed**
- Don’t make assumptions
- Better to ask than generate garbage
1. **Use consistent naming conventions**
- Follow ARTIFACT_NAMING_CONVENTION in master framework
1. **Reference previous artifacts**
- Don’t contradict earlier decisions
- Build on previous work
1. **Document deviations**
- If you must deviate from standards, document why
- Add to IMPLEMENTATION_NOTES.md

## TROUBLESHOOTING

### Problem: User uploads many files, unclear structure

**Solution**:

1. Start with Phase 6 (Recovery)
1. Use TEMPLATE_EXISTING_PROJECT_RECOVERY.md
1. Audit systematically
1. Create missing documentation

### Problem: Requirements keep changing

**Solution**:

1. Lock down requirements in Phase 1
1. Document changes in REQUIREMENTS_SPEC.md with version history
1. Assess impact on architecture/code
1. If major changes, may need to restart affected phases

### Problem: Phase validation fails repeatedly

**Solution**:

1. Identify root cause (missing info, contradictions, complexity)
1. Go back to previous phase if needed
1. Request user input for clarification
1. Don’t proceed until validation passes

### Problem: Codebase is too large to audit fully

**Solution**:

1. Start with entry points (main.py, app.py)
1. Map major components first
1. Do deep dive on critical paths
1. Flag areas needing human review
1. Prioritize by risk/impact

## FRAMEWORK PRINCIPLES

Remember these core principles:

1. **Structure prevents chaos**: Following process prevents “wildwuchs”
1. **Documentation enables continuity**: Future you/AI needs context
1. **Validation catches errors early**: Don’t compound mistakes
1. **Standards ensure quality**: Consistent code is maintainable
1. **Incremental progress**: Complete phases fully before proceeding

## WHEN TO USE THIS FRAMEWORK

### ✓ USE FOR:

- Any software project (new or existing)
- Projects prone to “AI slop”
- Multi-phase development
- Projects needing clear structure
- Code that must be maintainable
- Team projects requiring documentation

### ✗ DON’T USE FOR:

- Tiny scripts (<100 lines, single file)
- Throwaway prototypes
- Simple automation (unless it’ll grow)
- When user explicitly requests minimal process
