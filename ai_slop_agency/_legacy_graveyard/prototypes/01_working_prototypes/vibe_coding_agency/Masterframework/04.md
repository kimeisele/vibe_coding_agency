## SECTION 3: API SPECIFICATION

### FILE: API_SPEC.md

```markdown
# API Specification: [Project Name]

## API Style
**Type**: [REST, GraphQL, gRPC]
**Base URL**: `[https://api.example.com/v1]`
**Authentication**: [Bearer token, API key, OAuth]

## Global Headers
```

Authorization: Bearer {token}
Content-Type: application/json
Accept: application/json

```
## Endpoint Specifications

### ENDPOINT-001: [Endpoint Name]

**Method**: `[GET/POST/PUT/DELETE]`
**Path**: `[/api/resource/{id}]`
**Description**: [What this endpoint does]

**Path Parameters**:
- `id` (UUID) - Resource identifier

**Query Parameters**:
- `filter` (string, optional) - Filter results
- `limit` (integer, optional, default: 20) - Result limit
- `offset` (integer, optional, default: 0) - Pagination offset

**Request Body** (for POST/PUT):
```json
{
  "field1": "string (required)",
  "field2": 123,
  "nested": {
    "subfield": "value"
  }
}
```

**Response - Success (200/201)**:

```json
{
  "data": {
    "id": "uuid",
    "field1": "value",
    "field2": 123,
    "created_at": "2024-01-15T10:30:00Z"
  },
  "meta": {
    "timestamp": "2024-01-15T10:30:00Z"
  }
}
```

**Response - Error (400/404/500)**:

```json
{
  "error": {
    "code": "ERROR_CODE",
    "message": "Human-readable error",
    "details": {
      "field": "Additional context"
    }
  }
}
```

**Rate Limiting**:

- Limit: [100 requests per minute]
- Header: `X-RateLimit-Remaining: 95`

**Example Usage**:

```bash
curl -X GET "https://api.example.com/v1/resource/123" \
  -H "Authorization: Bearer {token}"
```

## DESIGN PATTERNS TO CONSIDER

### For Different Project Types:

**Web API**:

- Repository pattern for data access
- Service layer for business logic
- DTO pattern for data transfer
- Factory pattern for object creation

**Data Processing**:

- Pipeline pattern
- Strategy pattern for algorithms
- Observer pattern for events

**UI-Heavy**:

- MVC/MVVM
- Component-based architecture
- State management pattern
