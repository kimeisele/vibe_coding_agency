# EXISTING PROJECT RECOVERY TEMPLATE

## Phase 6: Legacy Codebase Remediation

-----

## INSTRUCTIONS FOR AI

This template guides analysis and recovery of EXISTING projects with chaotic or undocumented codebases.

### TYPICAL SYMPTOMS:

- “AI slop” (inconsistent AI-generated code)
- Missing or incorrect tests
- No clear architecture
- Unclear functionality
- Unmaintainable structure

### PROCESS:

1. Audit existing codebase
1. Categorize issues by severity
1. Create recovery roadmap
1. Generate missing documentation
1. Plan incremental refactoring

## SPECIAL CONSIDERATIONS FOR AI-GENERATED CODEBASES

### Common “AI Slop” Patterns to Identify:

1. **Over-abstraction**: Unnecessary classes/patterns
1. **Incomplete error handling**: Try-except with just `pass`
1. **Inconsistent style**: Mixed conventions in single file
1. **Redundant code**: Multiple implementations of same logic
1. **Missing edge cases**: Happy path only
1. **Over-commenting**: Obvious comments, under-explaining complex parts
1. **Cargo cult patterns**: Using patterns inappropriately

### Recovery Strategy for AI Slop:

```
1. Identify coherent "islands" of functionality
2. Extract and preserve working core logic
3. Rebuild structure around proven components
4. Add proper error handling and validation
5. Write tests for actual behavior
6. Document as-is, not as-intended
```
