### Epic 2.1: Refactor Task Handler System
**Priority:** P0 (Critical for `os` command scalability)

**Problem:** `core/task_handlers.py` ist ein monolithischer Registry (8+ handlers in einer Datei).

**Solution:** Implement a proper **Task Handler Plugin System** (wie Provider-Pattern).

#### Task 2.1.1: Create Task Handler Base Class
```python
FILE: agency_toolkit/tasks/base.py
TASK: "Create abstract base class for task handlers"

CODE:
from abc import ABC, abstractmethod
from typing import Any
from pydantic import BaseModel

class TaskContext(BaseModel):
    """Type-safe context for task execution."""
    config: Any  # Will be typed later
    step_context: dict[str, Any]
    archetype_id: str | None = None
    solution_id: str | None = None

class TaskHandler(ABC):
    """Base class for all task handlers."""

    @property
    @abstractmethod
    def name(self) -> str:
        """Unique task name (e.g., 'ai', 'social')."""
        pass

    @abstractmethod
    def execute(
        self,
        params: dict[str, Any],
        context: TaskContext
    ) -> dict[str, Any]:
        """Execute the task and return results."""
        pass

    @abstractmethod
    def validate_params(self, params: dict[str, Any]) -> None:
        """Validate params before execution (fail-fast)."""
        pass

VALIDATION:
  - File exists at correct path
  - Can be imported: from agency_toolkit.tasks.base import TaskHandler
  - No syntax errors
```
**Estimated Time:** 30 minutes
**Dependencies:** None

#### Task 2.1.2: Create Task Handler Registry
```python
FILE: agency_toolkit/tasks/registry.py
TASK: "Create dynamic task handler registry (like provider_loader.py)"

CODE:
from typing import Type
from .base import TaskHandler

_TASK_HANDLERS: dict[str, Type[TaskHandler]] = {}

def register_task_handler(handler_class: Type[TaskHandler]) -> None:
    """Register a task handler."""
    handler = handler_class()
    _TASK_HANDLERS[handler.name] = handler_class

def get_task_handler(name: str) -> TaskHandler:
    """Get a task handler instance by name."""
    if name not in _TASK_HANDLERS:
        raise ValueError(f"Unknown task handler: {name}")
    return _TASK_HANDLERS[name]()

def list_task_handlers() -> list[str]:
    """List all registered task handler names."""
    return list(_TASK_HANDLERS.keys())

VALIDATION:
  - Can register and retrieve handlers
  - Raises ValueError for unknown handlers
```
**Estimated Time:** 20 minutes
**Dependencies:** Task 2.1.1

## 🎛️ Execution Strategy for AI Agents

### Safe Task Characteristics
✅ **Auto-approve these:**
- Any task with "Auto-fix" or "Format"
- Tasks marked "VALIDATION: All tests pass"
- Tasks with CC reduction goals
- Documentation updates

⚠️ **Human review required:**
- Tasks changing `orchestrator.py`
- Tasks touching `models.py` (Pydantic schemas)
- Any task marked "MEDIUM" or "HIGH" risk

### Rollback Strategy
Each task should create a git commit:
```bash
git checkout -b task-2.1.3-ai-handler
# ... work ...
git commit -m "Task 2.1.3: Migrate AI task handler to plugin"
git push origin task-2.1.3-ai-handler
# If breaks: git revert HEAD
```

## 🚨 Critical Gotchas for AI Agents

1. **Never modify `models.py` without explicit instructions**
   - Pydantic validators have complex side effects

2. **Always run tests after each task**
   - Command: `pytest tests/ -v`

3. **Keep old imports working during migration**
   - Use deprecation warnings, not immediate deletion

4. **Task 2.1.5 is the "point of no return"**
   - After this, old TASK_REGISTRY is gone
   - Test extensively before merging

## 🔮 What This Achieves

**Before:**
```python
# Fragile string-based task dispatch
TASK_REGISTRY = {
    'ai': lambda task, ctx: complicated_logic(task, ctx),
    'social': lambda task, ctx: more_logic(task, ctx),
}
```

**After:**
```python
# Type-safe, testable, extensible
class AITaskHandler(TaskHandler):
    def validate_params(self, params: dict) -> None:
        # Fail fast on missing params

    def execute(self, params: dict, context: TaskContext) -> dict:
        # Pure business logic
```

**Result:**
- ✅ Showcase-ready architecture
- ✅ Easy to add new task types
- ✅ AI agents can safely modify handlers
- ✅ Clear separation of concerns
